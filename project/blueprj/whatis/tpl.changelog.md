## Project Changelog

The project shall uses this [Changelog template][changelog whatis] to track project's changes across:
- document baselines
- major milestones
- project documents
- software releases
- system architecture deliverables.

The format is 





<h1 align="center">Project: Blue - Changelog Template</h1>

A **Changelog** template for the software project based on [Keep a Changelog][changelog whatis] standard,which adheres to [Semantic Versioning][semantic versioning whatis].

# Reference Labels

When logging changes group items using these standard labels:

| Category | What to Log |
| --- | --- |
| **Baseline Documents** | List of key document IDs and versions frozen/approved in this release. |
| **Added** | New documents, features, specifications, or architectural components. |
| **Changed** | Modifications to existing requirements, designs, or project scope. |
| **Deprecated** | Features or specifications marked for removal in upcoming versions. |
| **Removed** | Features, documents, or requirements officially dropped from scope. |
| **Fixed** | Corrections to mistakes, ambiguous specs, or conflicting requirements. |
| **Security** | Security mitigations, vulnerability fixes, or compliance audit updates. |
